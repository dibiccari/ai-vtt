# AI-VTT

Self-hosted D&D 5e virtual tabletop. **Claude (Anthropic API) is the Dungeon Master**; the browser draws the battlemap and speaks the DM's replies. Currently loaded with the *Lost Mine of Phandelver* campaign.

## Run it

```
npm install
npm run dev      # node --watch server.js  -> http://localhost:3000
npm run check    # syntax-checks server.js and the inline <script> of public/index.html
```

Keys live in `.env` (git-ignored). Easiest way to set them: open **Settings** (`/settings.html`) and paste them in. It writes `.env` and applies instantly, no restart. `.env.example` lists every variable.

## What git tracks

Everything is tracked except five things: **`.env`** (the only file with secrets: API keys, set on the Settings page), `node_modules/`, `.DS_Store`, `data/tts-cache/` (voice clips, regenerated on demand) and `data/usage.json` (your own AI usage totals). The user chose (Oct 2026) to track the maps, tokens, sheet PDF and campaign data too, so a fresh clone works after `npm install` plus a `.env`. That includes copyrighted material (the Lost Mine text in `data/campaigns/`, the Phandelver and purchased dd2vtt maps in `public/uploads/`, the Drive token art in `public/tokens/`, the WotC sheet in `public/sheets/`), so check the licences before pushing to a public repository. Never commit `.env` or paste a key anywhere. Campaign saves (`data/campaigns/<id>/save.json`, the journal) are tracked too, so they show up as changes while you play.

## API (server.js)

- `GET/POST /api/characters`, `DELETE /api/characters/:id`: sheets as JSON files. A character may carry `sheet` (PDF field name to value); a POST without `sheet` keeps the stored one. The record's name/class/level/HP/AC/speed/abilities are what the tabletop uses.
- Map changes: `lib/campaign-maps.js` lists the places each campaign can use (installed map file, kind regional/town/battle, a description the AI reads, arrival spots as tabletop squares). The DM can return `changeMap` (mapId, arrive, reason); `/api/chat` resolves it to a map url and arrival square (unknown ids come back as a problem note) and the tabletop's `travelTo()` moves the table: it remembers the scene being left (creatures + party positions per map, kept in the saved board), shows the new map, places the party, and sets grid/fog for the map kind (regional and town maps are plain pictures: shown whole, no grid, no fog, no tokens drawn, fog/movement controls disabled; only battle maps have tokens and fog). `GET /api/maps/available` feeds the Map picker in the top bar. A map with a saved calibration (`squares` in data/maps/*.json, set on the Map Test page) is drawn so one printed square = one board square.
- Each campaign keeps its own saved board and chat in this browser (`vtt.board.<campaignId>`, `vtt.chat.<campaignId>`); the tabletop loads the ones for the active campaign and reloads when the active campaign changes elsewhere. A campaign with no saved board starts from its ready-made scene in `public/scenes.js` (Lost Mine: the Sword Coast regional map, shown whole with no grid, fog or tokens; the tavern scenario: the Rusty Flagon). The old single `vtt.board`/`vtt.chat` keys are no longer used. The Campaigns page can start a campaign over (clears its saved board and chat).
- Conditions: each token has `conditions` [{name, rounds}] (5e conditions, concentrating, or a free effect name; rounds 0 = until removed). Double-click a token to set them; badges show on the token and the turn bar; timed ones tick down each new round. blinded/unconscious shrink a PC's sight to 1 ft (house rule), an invisible NPC is not seen by the party. The DM sends addCondition/removeCondition.
- Board updates the tabletop applies (mapUpdates, after the server expands the DM's flat `token` updates): moveToken, addToken, removeToken, setHp, addWall, revealToken, hideToken, addCondition, removeCondition, changeMap. Tokens carry `hidden` and `kind` ("creature" or "trap"). The tabletop decides what the players see in `seenByParty()`: player tokens always; anything else only if it is not hidden and, while fog is on, inside a party member's current line of sight. Hidden/unseen tokens are not drawn, not in the turn bar, not in chat notes, not clickable, and are skipped by End Turn; the DM-view checkbox shows them as ghosts. The chat request sends each token's `hidden`, `kind` and `visibleToParty`, and the DM prompt forbids mentioning hidden things.
- The DM can edit player character sheets with the `updateCharacter` update (edits like classLevel/xpGain/maxHp/hp/str..cha or any official sheet field name, plus skills, saves, spells, slots; the model sends them all in one `edits` list, see the DM reply schema note). `lib/sheet-edit.js` applies it on the server inside `/api/chat`: it keeps modifiers, proficiency bonus, passive Perception and HP consistent, refuses name changes, saves the character, appends to `character.sheetLog` (shown with Undo on the Character Sheets page), and `/api/chat` returns `characterUpdates` for the tabletop to show. `lib/sheet-fields.json` is the field map (spell lines per level, slots) derived from the official PDF. The AI's reply schema is an `anyOf` of update types with all fields required, because the API rejects more than 24 optional schema fields. Level-up is a conversation driven by the DM prompt: it asks the player's choices first and only then calls updateCharacter.
- `GET /api/campaigns` (list + stats), `POST /api/campaigns/active {id}`, `GET/PUT/DELETE /api/campaigns/:id/files/:name` (PUT/DELETE and the active switch are local-only). The server loads the active campaign's text per request (cached until a file changes) and sends it to the DM as a cached system block.
- Audio and mood (public/ambience.js, window.Ambience): everything is synthesised with the Web Audio API (no sound files, nothing to license): ambient scenes (forest, night, wind, cave, dungeon, tavern, town, rain, fire), moods (calm, tense, combat, eerie, triumph) and one-shot effects (door, creak, thunder, bell, roar, howl, clash, magic, explosion, splash). A map config may name its sound (`ambience`, set on Map Test); otherwise it follows the kind of place and its light (`ambienceScene()`). Combat sets the combat mood by itself; the DM sends token actions mood and sfx. The ambience ducks while the DM speaks, starts on the first click (browser rule), and has a checkbox and volume in the chat panel (localStorage vtt.ambience, vtt.ambienceVol). It was only checked by measuring that each scene, mood and effect produces signal (`Ambience.level()`); how it SOUNDS is for the user to judge.
- Safety tools: `data/campaigns/<id>/safety.json` {lines, veils, notes} (lib/safety.js; edited on the Campaigns page "Safety" button; `GET/PUT /api/campaigns/:id/safety`, PUT local-only). `/api/chat` adds a TABLE SAFETY block to the DM system prompt when there is one, and the DM prompt explains the X-card: the tabletop's ⏸ Pause button sends a message containing [PAUSE] and the DM must stop the scene and check in.
- Campaign maps: the Campaigns page "Maps" button edits which maps a campaign can use (picture, name, kind battle/camp/town/regional, the description the DM reads) and saves `data/campaigns/<id>/maps.json`; with no maps.json the built-in registry in lib/campaign-maps.js is used (`mapsForCampaign()` in server.js). `GET/PUT/DELETE /api/campaigns/:id/maps` (PUT/DELETE local-only). Arrival is the map's `start` pin.
- Scenes (the 💾 Save scene button, Scenes picker and 💡 Light button still exist in the tabletop page but are always hidden, since they are setup tools): a saved map + its creatures, traps and lights, per campaign in localStorage `vtt.scenes.<campaignId>` (included in the Journal page export/import). Loading one replaces the creatures (travelling to the map if needed, via the map memory).
- Summons: tokens with `summon` {kind mage-hand|spiritual-weapon, ownerId, rounds, leashFt} (presets in `SUMMONS`, `conjure()`; combat panel "Conjure" select or the DM token action summon). They move (drag) on their owner's turn within their own speed and leash (`reachable()` filters by distance from the owner), are never in the initiative order or End Turn loop, and expire after their rounds (ticked in `tickConditions()`). Conditions now change speed (`effectiveSpeed()`: grappled/restrained/paralyzed/petrified/stunned/unconscious 0, prone half) and chips show a rules tooltip (`CONDITION_HELP`).
- Object tops (shared public/wallobjects.js, used by the tabletop and Map Test): small closed wall loops (tents, boulders, crates, tree trunks; anything up to 9 squares across) are found by chaining wall segments (`WallObjects.loops()`) and their tops are revealed through the fog whenever any party member can see their edge (`revealObjectTops()`), so line of sight stops at them but they do not look like black holes. Rooms and big structures are not treated as objects.
- Map making (lib/mapkit.js): a Painter (antialiased shapes on an RGBA buffer, glow, PNG encoder) and a Level that collects walls, doors and lights while you draw (`level.solid(corners)`, `level.wall()`, `level.door()`, `level.light()`, `level.write()`), plus `nightFrom()`. scripts/make-camp-map.mjs (older, self-contained) and scripts/make-dungeon-map.mjs (uses mapkit: a floor-cell grid whose floor/rock edges become the walls, thick stone wall cells, doors, props that add their own outlines, torches that flicker) write public/scenarios/*.dd2vtt; import with scripts/import-dd2vtt.mjs, then set `light`, `ambience` and a `start` pin in the map config (the camp and dungeon-cellars configs were done by hand). Workflow: write, view the picture (it writes public/scenarios/.preview-*.png, git-ignored), iterate, import, look at it on the tabletop with fog on.
- Flicker (public/flicker.js): map lights with `flicker: true` in the map config (the camp's campfire; set in data/maps/*.json, kept by the server) are animated over the picture on the tabletop and Map Test: a wavering glow, flame tongues, hot core and embers, redrawn about 15 times a second only while such a light is on. Map Test's Reset explored and Fit view buttons now sit beside the Day/Night switch. The old "Send walls to tabletop / Load walls from tabletop" buttons were removed (walls come from data/maps).
- Lighting (public/index.html "LIGHTING"): each map config has `light` (bright | dim | dark, set on Map Test; default bright) and its dd2vtt `lights` (image px, `range` in squares = dim radius, bright = half; optional `name`). The table can override the level (💡 Light button) and put map lights out; tokens can carry a light (torch 20/40 ft, lantern 30/60, candle 5/10, Light spell 20/40: double-click a token). Characters have `darkvision` ft (Party page). Rules: bright/dim = line of sight is enough (no distance cap any more); dark = only what a light source lights (its own sight polygon, bright to the bright radius, dim to the dim radius) or the character's darkvision reaches; blinded/unconscious = own square only. `lightLevelAt()`, `visibleFrom()`, `revealFog()` (drawn on reduced-size canvases for big maps) and `seenByParty()` use it, so hidden-token rules follow. The DM gets a lighting block (ambient, map lights with ids) and sends token action light (token carries torch/lantern/candle/light/none, or map light id with value 1/0). not done: per-area light zones (removed), coloured light, and Map Test does not simulate lights.
- Tabletop controls: the Map picker is hidden (the DM moves the table between maps with changeMap; `renderMapPick()` and `state.visitedMaps` remain in the page but nothing shows them); the Fog of war checkbox, Reset fog and DM view are hidden there (fog is on by default; the Test Lab has the Fog and DM view options, DM view on by default, and sets `vtt.dmView`).
- Table settings (lib/settings.js, `data/campaigns/<id>/settings.json`, Campaigns page > Settings; `GET/PUT /api/campaigns/:id/settings`, PUT local-only): `permadeath` (default OFF: a character who would die is left out of the fight and the story takes a setback; the tracker marks them stable instead of dead), `rules` ('2014' default, or '2024') and free `tableNotes`. `/api/chat` gives the DM a TABLE SETTINGS block every turn. Lost Mine is set to 2014, no permadeath, with the table's notes.
- Characters belong to campaigns: a character file may carry `campaigns` [ids]; `GET /api/characters?campaign=<id>` returns only that party (no `campaigns` = every campaign), and the tabletop, party page, rests and the DM's party block use the active campaign's party. The Lost Mine party (Edric, Raechyl, Shadowheart, Astarion; level 1, 2014 rules, official-sheet fields filled) is generated and checked by `node scripts/make-lmop-party.mjs`; Thorin, Lyra, Vex and Seraphine are tagged for the tavern test and are filled in (level 3: weapons, spells, slots, gear; the definitions are in `lib/tavern-party.js`) by `node scripts/make-tavern-party.mjs` (keeps their current hit points; `--full` restores them) and by the Test Lab, which resets them to that starting kit with full hit points every time it starts the scenario (`POST /api/test-lab/reset-party`); both party scripts build sheets with `lib/charbuild.js`. Raechyl keeps her old hill-dwarf ability scores as a tiefling (the table's choice; the 2014 tiefling would add +1 INT, +2 CHA).
- Dice (lib/dice.js; `node scripts/test-dice.mjs` rolls every die 60,000 times and checks range, evenness, advantage/disadvantage and the parser): all rolls use crypto.randomInt. `POST /api/roll {expr, mode}` (free) backs the tabletop's Roll for me; every `/api/chat` board state carries a `diceTray` of real pre-rolled dice the DM must take from in order, because a model cannot make random numbers. Dice mode: 'ai' (the DM rolls for the players) or 'player' (the DM asks for the roll and waits); in both the player can type what they rolled, or say "roll for me" (the die picker row, with Roll for me and `POST /api/roll`, is still in the page but hidden).
- Turns: the AI tracks turns and the tabletop has no turn bar, End Turn button or Next turn button. Outside combat there are no turns: any party token can be dragged at any time (up to `FREE_ROAM_FT` = 150 ft per drag, walls and doors still block, no budget spent; grabbing a token makes it the speaker). In a fight only the active token moves (movement is round on every map: straight-line distance, a circle outline of the speed; a diagonal square costs about 7 ft; this is not the 5e grid rule where a diagonal costs 5 ft; the Movement drop-down was removed; the range outline shows only in a fight) and the player tells the DM when they are done (typing or voice); the DM then sends token action `endTurn` with the active token's id to advance the tracker, plays each creature's turn, and sends `endTurn` for each, until a player character is up. After each reply the table asks the DM to play any creature that is active (`aiTakesItsTurn()`). `?nosave=1` on the tabletop address stops it writing the server save (for testing).
- Rolls in the chat: the DM reply has a `rolls` list (one short line per roll: attacks, damage, saves, checks, initiative, death saves, and numbers the players report) that the tabletop prints as 🎲 lines before the narration; initiative the table rolls itself prints too (browser rolls use crypto.getRandomValues).
- The tabletop has no Send button: Enter sends (Shift+Enter is a new line; voice sends on release), and the AI takes its own turns: after every successful reply, if the tracker sits on a creature the table sends the DM "[Table] It is <name>'s turn." (`aiTakesItsTurn()`, at most 12 in a row, never shown in the chat) until a player character is up.
- data/reference/lmop-session-1-handoff.md: the previous AI DM's session-1 handoff (style rules, party, story, where they stopped). Reference only, never given to the DM; the new Lost Mine run starts at level 1 / XP 0 to compare against it.
- Campaign setup of maps: Campaigns > Maps shows each map's setup (thumbnail with its start pin, start pin set or missing, grid calibrated or not, light level, walls) from `GET /api/map-configs` and a "Set up this map…" link that opens Map Test on that picture (`map-test.html?map=/uploads/<file>`). Start pins are drawn only on Map Test and that setup page, never on the tabletop.
- New campaigns (Campaigns page > New campaign, `POST /api/campaigns/new {template, name, party, settings}`, local-only): another playthrough of an existing campaign. It copies the template's documents, voices.json and maps.json, so its maps and their starting positions are already chosen (not the journal, party stash, safety or chat), and takes the party and the table settings from the form. campaign.json holds `template` and `party` (a list of character ids; also editable on the Settings panel, `GET/PUT /api/campaigns/:id/party`); with a `party` it wins over a character's own `campaigns` tag. A campaign shares its template's maps list (when it has no maps.json of its own) and starting scene (scenes.js is keyed by template); start pins live with the picture in data/maps. `GET /api/campaigns` returns each campaign's `template`. The Lost Mine campaign's party is Edric, Raechyl, Shadowheart and Astarion.
- Encumbrance: standard rule by default (no penalty up to Strength x 15 lb); the optional variant (encumbered over x5, heavily over x10) is a campaign setting `variantEncumbrance`, passed to `computeEffective(character, variant)` and told to the DM.
- Saved game on the server: the tabletop keeps the board, chat and explored fog in the browser and mirrors them to `data/campaigns/<id>/game.json` (savedAt, board, chat) and `fog.json` (map url to fog PNG) through `GET/PUT/DELETE /api/campaigns/:id/game` and `PUT .../game/fog` (`serverSave` in index.html: pushes 1.5 s after a change; at start-up the newer of the browser copy and the server copy wins, compared by `vtt.savedAt.<id>`). Start over deletes both copies; the Journal page's Import save marks the browser copy as newest.
- Difficult terrain: a map config may carry `difficult` (rectangles in image pixels, snapped to the grid; painted with Map Test > Terrain, right-click removes). The tabletop turns them into squares (`isDifficult()`), and when a map has any, movement range and moves use a shortest-path search (`reachTerrain()`) where entering a difficult square costs double (the 'round' rule's diagonals are then path-based: 7.07 ft per diagonal step). Map Test has a Movement range check box (test token, speed slider, per-square cost) to try it. Terrain Test Grounds (scripts/make-terrain-test-map.mjs + scripts/apply-map-sidecar.mjs; a Map Test map only, first in its list, not part of any campaign): a creek, trees, boulders, a rubble field with a ruined wall and a thicket, for trying fog of war, line of sight and difficult terrain.
- No campaign chosen: `data/campaigns/active.json` can be absent. `GET /api/campaigns` then returns `active: ''` (`chosenCampaignId()`; the rest of the server still falls back to Lost Mine through `getActiveCampaignId()`), the tabletop shows 'No campaign selected' with a link to the Campaigns page (`showNoCampaign()`), `/api/chat` answers 409, and the Journal says so. Pressing Continue on a campaign writes active.json.
- The combat panel has no buttons: the DM ends a fight (token action endCombat) when it is over or when you ask it to.
- Combat panel layout: the tracker sits on the left edge of the map pane (`.map-body`: tracker then map), only while there is a fight. One compact line per combatant (initiative, name, conditions, hit points, AC); the active combatant opens up (actions used, change hit points, death saves) and any other row opens with its arrow. The initiative rolls print as a single chat line. The map pane has no square-count or zoom readout.
- Start over: `POST /api/campaigns/:id/start-over` (local-only) clears everything the story built up: the saved game and fog, the journal the DM reads every turn and the shared stash. The Campaigns page Start over and the Test Lab both use it (the Test Lab also resets its four characters). Bug fixed Oct 2026: the Test Lab used to leave the journal, so a second run had the DM believing the first run's brawl was still going.
- Begin the adventure: while the DM has said nothing in a campaign (no assistant message in the chat), a gold "Begin the adventure" box with a button shows above the dice row; it sends [BEGIN] and the DM opens the story at the module's first scene (DM_SYSTEM "Beginning the story"). One AI call, only when pressed.
- Split party: a PC token can carry `where` (a short note). Token actions `away` (note in condition) and `here` set it (typed update `setWhere`). A character who is elsewhere is not drawn, not clickable, gives no vision, is left out of the combat order and of map moves (`isElsewhere()`), and is listed in the "Elsewhere" line of the map bar; the DM sees `where` on the token.
- Delay and DM-only notes (public/combat-order.js, pure helpers tested by `node --test test/`): token action `delay` (active combatant only; the table moves on, `t.delayed`, badge ⏸, skipped by `nextCombatTurn()`) and `resume` (initiative becomes the point just after whoever is acting, `CombatOrder.resumeInitiative`; the value can be fractional, shown rounded); a delayer still waiting when the round wraps acts in their usual slot. No player button: they tell the DM. Token action `note` (text in `condition`, empty clears) sets `t.dmNote` (saved in the board, sent to the DM in the tokens); tokenId `dm` sets the campaign scratchpad `state.dmPad` (sent as `dmPad`, the DM sees `dmScratchpad`). Notes are never printed in chat; the 🗒 chip and pad show only with DM view on (Test Lab). A resumed delayer is placed right after the combatant acting (`t.actsAfter`, `CombatOrder.placeAfter`, applied in `sortCombat()`, cleared when their turn starts), also on a tied number. Reactions: `t.spent.r` is the reaction (reset in `beginTurn()`, shown struck through in the row); token action `react` spends it, `ready` spends the action and, when sent again with no text (trigger), the reaction. The opportunity-attack note to the DM lists who may attack and who cannot and why (reaction used, incapacitated, down...); the DM rolls and sends `react`. Browser test `combat extras together` covers all of this.
- Token sizes, height and flight (Nov 2026; public/token-size.js pure helpers, tests in test/token-size.test.mjs and the sizes/haste/flying tests of test/browser): a token has `size` (tiny..gargantuan; from the SRD or monsters.json entry on add, `condition` text for other creatures, Medium for characters unless the character record has `size`; token action `resize` changes it). Footprint: tiny/small/medium 1 square (tiny drawn half size), large 2x2, huge 3x3, gargantuan 4x4; `(col,row)` is the TOP-LEFT square (`fp(t)`, `tcx/tcy` give the footprint centre, used for drawing, hit-testing, the HP bar, badges, the range circle, drag, light and spell origins and the sight origin). Movement (`reachable()` with `moveN`): every square of the body moves along the same step and none may cross a wall, a wall inside the destination footprint blocks, the whole body must be on the map and may not end overlapping another token; squeezing through a space one size smaller is NOT implemented. A token is seen when any square centre of its body is in sight; reach is edge to edge (`TokenSize.gap`), a spell area catches a creature when any square of its footprint is inside (`insideTemplateFp`). `freeSquareNear(col,row,n)` finds room for the whole body; a big creature added exactly on a module-area pin is centred on it (`TokenSize.topLeftFor`). The DM returns `journal` updates (category event/npc/quest/place/loot/promise, title, text, status, when; non-event titles are upserted); `/api/chat` stores them via `lib/journal.js` and the journal is sent to the DM as an uncached system block after the campaign text. `GET/PUT /api/campaigns/:id/journal` (PUT is local-only), `POST /api/recap` (one paid call; "Previously on..."; the tabletop's Recap button speaks it). Campaigns > Start over also clears the journal.
- Arrival spots: the Map Test page has a Pins tool (click empty ground to add a pin with the name in the box, drag to move); named spots (`start` = default) are saved in the map config as `starts` (image pixels). `withSavedStarts()` in server.js adds them to the map registry (they win over the by-eye guesses in lib/campaign-maps.js) and the tabletop turns pixels into squares in `travelTo()`.
- `node scripts/import-dd2vtt.mjs <file.dd2vtt> <name>` imports a .dd2vtt (picture to public/uploads, walls/doors/grid/lights/ambient to data/maps). The Lost Mine maps came from the user's "LMoP Pack.zip" (Map Adventurer, 70 PPI): Summer variants, Redbrand Main, Cragmaw Castle day+night, Wave Echo Cave Desert. Cragmaw Hideout, Goblin Ambush and Wyvern Tor have no walls in the pack. Their arrival squares in lib/campaign-maps.js are bottom-centre placeholders until set with Set start.
- Map groups: a map config may carry `group` and `variant` (e.g. cragmaw-castle / day, night); Map Test shows a Day/Night (any versions) switch in the top-left of the map for grouped maps and keeps the zoom when switching. Set on the Map Test page (Group, This version is called). The AI-facing registry in lib/campaign-maps.js does not use groups yet (Cragmaw Castle day and night are still two entries).
- Live view (multiplayer phase 0): lib/live.js keeps a revision per campaign and `GET /api/campaigns/:id/live` is a server-sent-events stream (`hello`, then `change` {rev, scope, at}) announcing every successful write to that campaign's game, journal, party, settings..., or to characters/party/chat; `GET .../game` returns `rev` too. public/watch.js + `/?watch=1` is the read-only spectator tabletop: all non-GET fetches are refused in the page, editing controls hidden, and it reloads itself when the saved game changes (`serverSave.pull` takes the server copy in watch mode). Not authenticated and not filtered (a watcher gets the full board); there is no joining or seats yet.
- `GET/PUT /api/map-config?map=<file>`, `GET /api/map-configs`: per-map walls/doors/grid in `data/maps/` (PUT is local-only).
- `POST /api/upload` (field `map`), `GET /api/maps`, `GET /api/tokens`.
- `POST /api/chat`: `{message, history, tokens, characters, walls, gridSize, mapName, inputMode}` returns `{narrative, voiceLines[{speaker,voice,text}], mapUpdates[]}`. Uses `claude-opus-5-5`, structured JSON output (`output_config.format`), the campaign text as a cached system block, and `fallbacks: 'default'`. `mapUpdates` types: moveToken, addToken, removeToken, setHp, addWall.
- `GET /api/tts/status`, `POST /api/tts`, `POST /api/tts/voices`: OpenAI text-to-speech (`gpt-4o-mini-tts`). Clips are cached on disk. Named NPCs use the active campaign's `voices.json`; others get a voice by style tag.
- `GET/POST /api/settings`, `POST /api/settings/test`: **local-only** (loopback + Host/Origin checks). Never returns full keys. The server listens on `127.0.0.1` by default (`HOST` env to change).

- Sound takes: public/audio/candidates/ holds CC0 candidate clips (manifest.json, credited in public/audio/CREDITS.md) for bell, clash, creak, explosion, magic, roar, splash, howl, thunder. The Sound Test page plays each take and "Use this one" copies it to public/audio/sfx-<effect>.mp3 (POST /api/sound-choice, local-only; choice recorded in data/sound-choices.json). Not yet listened to by the assistant.

## Voices

Two engines, switchable any time (Settings page, chat-tab dropdown, voice-test checkbox; stored in `localStorage` key `vtt.voiceEngine`): **ChatGPT voices (OpenAI)** and **Microsoft/browser voices** (Web Speech API). Claude has no voice output. The DM labels each line with a voice tag (narrator, gruff, sly, noble, elderly, child, monstrous, ethereal, feminine, masculine, beast for a medium animal, smallbeast for small ones (high-pitched: mice, birds), largebeast for large ones (low-pitched: bears, horses), undead for ghosts and the dead; these were added Oct 2026 and have not been listened to). The mic is muted while the DM speaks (stream track disabled, recognizer stopped, 1.2 s grace) to stop it transcribing the narration. The speed parameter is ignored by `gpt-4o-mini-tts`, hence the browser-side effects in `voice-fx.js`.

## Conventions

- Complete code only: no placeholders, no truncation, no `...` elisions. The frontend stays a single `public/index.html` (plus the small shared scripts above).
- ES modules only. Match the surrounding style. Run `npm run check` after edits.
- Browser state is in `localStorage` (`vtt.board`, `vtt.chat`, `vtt.walls.<map>`, `vtt.fog.<map>`, `vtt.voiceEngine`, ...); always wrap in try/catch.
